# 金融概念 -> 开发模块映射

本文件把金融知识直接映射到后续系统开发任务，避免“学完不知道怎么写代码”。

## 核心映射总表

| 金融概念 | 主要模块 | 关键实现点 | 最小验收 |
|---|---|---|---|
| 交易时段与休市 | `data_handler` | 交易日历、时段校验 | 休市不下单 |
| 合约乘数/最小变动价位 | `data_handler` `execution_router` | 名义价值计算、价格步长修正 | 报价合法且仓位计算正确 |
| 主力切换与换月 | `data_handler` `strategy` `backtest` | 主连映射、换月规则、成本计入 | 到期前自动切换且可回测复现 |
| 订单类型与撮合 | `execution_router` `backtest` | 限价/市价处理、队列逻辑 | 订单状态机完整 |
| 手续费与滑点 | `backtest` `portfolio` | 成本模型、成交价修正 | 加成本后收益报告可复现 |
| 保证金与强平 | `risk_engine` `portfolio` | 保证金占用、强平触发条件 | 保证金不足时拒单/强平正确 |
| 仓位与杠杆 | `risk_engine` `portfolio` | 单标的/组合级限额 | 超限自动拦截 |
| 回撤控制 | `risk_engine` `monitoring` | 日亏损和最大回撤阈值 | 触发后停止开仓 |
| 绩效指标 | `backtest` `monitoring` | Sharpe/回撤/胜率/盈亏比 | 报告指标定义一致 |
| 相关性与分散化 | `portfolio` `risk_engine` | 相关性矩阵、风险预算 | 风险集中度可视化与告警 |
| 流动性与冲击成本 | `execution_router` `backtest` | 下单量约束、冲击模型 | 低流动性时自动降量 |
| 幂等与对账 | `execution_router` `monitoring` | 唯一订单 ID、重试与核对 | 重试不重复下单 |

## 模块优先级（建议开发顺序）

1. `data_handler`: 没有正确数据口径，后续模块都不可靠。  
2. `backtest`: 先验证策略与成本模型，再谈实盘。  
3. `risk_engine`: 把风险规则前置，防止错误交易。  
4. `execution_router`: 打通交易链路，保证状态可追踪。  
5. `portfolio + monitoring`: 实时看得见、算得对、追得回。

## 第一版配置参数建议清单

- 交易参数：交易时段、最小变动价位、最小下单单位
- 成本参数：手续费率、滑点系数、冲击成本系数
- 风控参数：单品种风险上限、杠杆上限、日亏损阈值、最大回撤阈值
- 执行参数：重试次数、撤单超时、订单状态查询间隔
- 监控参数：报警阈值、报警通道、报告刷新频率

## 进入编码前的最小准备

1. 明确首批交易标的（股票池或期货品种池）。  
2. 为每个标的补齐合约/交易元数据。  
3. 给出成本模型的初始参数（允许后续校准）。  
4. 设定硬风控阈值（禁止“先跑起来再说”）。  
5. 定义订单状态机（`new -> submitted -> partial_filled -> filled/canceled/rejected`）。
